## 1. 프로젝트 개요

- **프로젝트명**: AmuseFit (InpockMobile)
- **개발 기간**: 2025.06 ~ 2025.06 (약 1개월)
- **수행 방식**: **개인 프로젝트**
- **담당 범위**: 전체 앱 개발 (프론트엔드 + 백엔드 + 데이터베이스 설계 + 배포)
- **배포 현황**: Replit Autoscale 배포 완료

## 2. 클라이언트 요구사항 및 나의 역할

### 클라이언트 개요

> 피트니스 전문가(PT, 요가 강사, 헬스장 운영자, 영양사, 인플루언서)를 위한 올인원 비즈니스 네트워킹 플랫폼. 분산된 SNS와 예약 링크를 하나로 통합하고, 전문성을 어필할 수 있는 디지털 명함 역할을 제공합니다.
> 

### 요구사항 요약

- 카카오 소셜 로그인 및 SMS/이메일 실제 인증 시스템
- Instagram Reels 스타일의 버티컬 콘텐츠 갤러리 (이미지/영상/링크)
- 개인화된 공개 프로필 페이지 (amusefit.com/@username)
- 실시간 비즈니스 분석 대시보드 (방문수, 클릭률, 유입 경로)
- 모바일 퍼스트 반응형 디자인 + 브라운 테마 UI

## 5. 문제 해결 및 기술적 도전

### 문제

### 사례 1: 카카오 OAuth 불완전 회원가입 처리

> 카카오 로그인 시 이메일과 전화번호가 선택 동의 항목이라 필수 정보가 누락된 사용자가 발생. 이 상태로 서비스 이용 시 핵심 기능(알림, 인증)이 작동하지 않는 문제 발생.
> 

### **해결 방법**

OAuth 콜백에서 `isProfileComplete` 플래그를 검사하여, 필수 정보 누락 시 `/complete-registration` 페이지로 리다이렉트. 세션에 임시 사용자 ID를 저장하고, 추가 정보 입력 완료 시 DB 업데이트하는 **2단계 회원가입 플로우** 구현.

- Code
    
    ```
    if (!user.phone || !user.nickname) {
      req.session.incompleteUserId = user.id;
      return res.redirect('/complete-registration');
    }
    ```
    

### 사례 2: 외부 API 장애 시 인증 시스템 중단 위험

> Twilio(SMS), Brevo(이메일) 등 외부 API 서비스 장애 시 인증 불가로 서비스 전체가 중단될 위험. 특히 결제 연동 전 무료 티어 한도 초과 시 즉시 장애 발생.
> 

### **해결 방법**

**다중 폴백 체인** 구현. 이메일은 Brevo → Resend → SendGrid 순으로 자동 전환. SMS는 실패 시 개발 모드로 자동 폴백하여 콘솔에 인증 코드 출력. 이로써 **100% 서비스 가용성** 확보.
